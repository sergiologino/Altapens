# Push-уведомления (план внедрения)

Сейчас напоминания и тревожные сигналы отображаются **в приложении** (лента, обзор опекуна). **Push** требует отдельной цепочки: регистрация устройства, сервер, доставка через FCM (Android) / APNs (iOS) / Web Push (браузер).

## Локальные напоминания в web (реализовано)

- **Подопечный (senior):** в «Профиль» — разрешение браузера на уведомления и переключатель напоминаний; срабатывание в **назначенную минуту** по слотам из обзора (данные те же, что на «Сегодня»), пока открыта вкладка с приложением.
- **Ограничение:** это не серверный push: при закрытой вкладке уведомление не придёт. Дальнейший шаг — раздел «Web (браузер)» ниже (Service Worker + VAPID) и backend.

## 1. Backend

- Таблица `device_push_tokens`: `user_id`, `platform`, `token`, `created_at`.
- `POST /api/v1/notifications/devices` — сохранить/обновить токен (JWT).
- Сервис отправки: по событию «просрочен слот без подтверждения», «нет чек-ина за день к вечеру», «SOS» — ставить задачу в очередь (или вызывать FCM HTTP v1).
- Конфигурация: ключи Firebase / VAPID для Web — только на сервере и в CI secrets.

## 2. Web (браузер)

- Service Worker + Web Push (VAPID), запрос разрешения у пользователя.
- Подписка после логина; отправка `subscription` на backend.

## 3. Мобильная оболочка (Capacitor)

- Плагин `@capacitor/push-notifications`: разрешения, `registration` → токен на backend.
- Для Android — `google-services.json` и FCM; для iOS — capabilities Push + ключи в Apple Developer.

## 4. Триггеры (согласовать продукт)

- Просрочен приём (уже можно вычислять по слотам, как в API `today-doses`).
- Отсутствие отметки самочувствия к заданному часу.
- Подтверждённый SOS.

Этот документ фиксирует направление работ; реализация по шагам — отдельными задачами (backend → mobile → web).
