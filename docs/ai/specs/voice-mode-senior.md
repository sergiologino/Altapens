# Спецификация: двусторонний голосовой режим для подопечного (senior)

## 1. Цели и принципы

- **Доступность:** пользователь с ограниченной подвижностью зрения или моторики может пользоваться приложением без точного нажатия по мелким целям.
- **Двусторонность:**
  - **Ввод голосом (STT):** короткие команды и фразы на русском; распознанный смысл переводится в действия в приложении и/или на backend.
  - **Вывод голосом (TTS):** подсказки и вопросы приложения озвучиваются, когда включён голосовой режим.
- **Безопасность и ясность:** критичные действия (SOS, пропуск лекарства) подтверждаются голосом или крупной кнопкой после распознанного намерения.
- **Офлайн-ожидания:** на **веб-клиенте** полноценный офлайн STT недоступен; явно коммуницировать «нужен интернет» для распознавания (если используется браузерный движок с облаком).

## 2. Область применения (MVP)

### 2.1 Сценарии пользователя (примеры → продуктовое действие)

| Фраза (пример) | Намерение | Действие MVP |
|----------------|-----------|----------------|
| «Я выпил таблетку валидола» / «принял корвалол» | Отметить приём | Сопоставить название препарату из **сегодняшних слотов** (нечёткое совпадение); при однозначном совпадении — `POST /care/medications/intake` (`taken`); иначе — озвучить уточнение и показать выбор слота. |
| «Пропустил утреннее лекарство» | Пропуск | Аналогично, статус `missed`, с подтверждением. |
| «Давление 120 на 80» | Зафиксировать показатель | **MVP:** создать **чек-ин** с `note` = полная фраза или структурированная строка; **следующая фаза:** отдельная сущность «измерения» (Flyway + API). |
| «Позвони дочери, мне плохо» | Срочная помощь | Навигация на экран **SOS** + TTS «Сейчас откроется экстренный экран»; опционально `POST /care/checkins` с `state: bad` и `note` (политика продукта: согласовать, чтобы не дублировать SOS). |

### 2.2 Сценарии приложения (TTS)

- При появлении ключевых экранов (или по кнопке «Озвучить экран»): краткая сводка.
- **Чек-ин:** озвучить вопрос: «Как вы себя чувствуете?» и перечислить варианты с номерами («Скажите один — хорошо, два — нужна помощь…») — **или** после объявления вариантов ждать свободную формулировку и маппить на `good` / `need_help` / `bad`.
- **Лекарства:** «Пора принять [название], [доза]» по расписанию (по таймеру или при открытии «Сегодня»).

## 3. Платформа и технологии (web MVP)

### 3.1 TTS (озвучка)

- **Web Speech API:** `window.speechSynthesis` с выбором голоса `lang: 'ru-RU'` (доступность голосов зависит от ОС/браузера).
- Очередь реплик, отмена при уходе со страницы, пауза при системных прерываниях (по возможности).
- Учитывать переключатель **«Озвучка»** из `accessibility-store` и флаг **`voiceEnabled`** в профиле (в будущем синхронизация с backend при сохранении профиля).

### 3.2 STT (распознавание)

- **Web Speech API:** `SpeechRecognition` / `webkitSpeechRecognition` с `lang: 'ru-RU'`.
- **Режим взаимодействия:** по умолчанию **нажал и держишь / нажал начать — нажал стоп** (push-to-talk), чтобы снизить ложные срабатывания и шум; опционально позже — непрерывное прослушивание с ключевой фразой (сложнее в браузере).
- Требования: **HTTPS**, разрешение микрофона; обработка `not-allowed`, `no-speech`, таймаутов с дружелюбным TTS.

### 3.3 Ограничения браузера (матрица на 2026)

| Платформа | TTS (озвучка) | STT (ввод) | Примечание |
|-----------|---------------|------------|------------|
| Chrome / Edge (desktop, Android) | Обычно да | Обычно да (`ru-RU`) | Основной целевой режим; нужен HTTPS (кроме localhost). |
| Firefox | Зависит от ОС | Часто нет API | Показывать подсказку «используйте кнопки». |
| Safari (macOS / iOS) | Частично | Частично / нестабильно | Проверять вручную; fallback на кнопки. |

- Долгосрочно: нативная оболочка (Capacitor / PWA + нативный плагин) для стабильнее STT на Android.

## 4. Архитектура frontend

```
features/voice/
  voice-tts.ts          // обёртка над speechSynthesis, выбор голоса
  voice-stt.ts          // push-to-talk, поток распознанного текста
  voice-intents.ts      // правила + нормализация текста → Intent
  voice-router.tsx      // связывает Intent с mutation (intake, checkin, navigate)
  SeniorVoiceBar.tsx    // UI: микрофон, индикатор слушания, подсказки
```

- **Intent (MVP):** дискриминированное объединение: `MedicationTaken`, `MedicationMissed`, `MedicationSnoozed`, `CheckinState`, `VitalsNote`, `NavigateSos`, `Unknown`.
- **Разбор текста:** слой 1 — ключевые слова и шаблоны (регулярки, список синонимов препаратов из загруженных `today-doses`); слой 2 (опционально) — вызов backend **или** LLM только для классификации намерения (отдельное решение по ПДн).

## 5. Backend

- **Без обязательных новых эндпоинтов для MVP**, если достаточно существующих: `checkins`, `medications/intake`, навигация на клиенте.
- **Следующая фаза:** `POST /care/voice-command` с телом `{ rawText, clientIntent?, locale }` — сервер валидирует и возвращает безопасное действие (audit, защита от подделки не критична для MVP семейного приложения).
- **Измерения давления:** позже — `wellbeing_measurements` или расширение чек-ина; в спецификации зафиксировать временное сохранение в `checkin.note`.

## 6. UX и доступность

- Крупная кнопка микрофона, haptics не обязательны на web.
- Визуальная обратная связь: «Слушаю…», распознанный текст на экране до подтверждения.
- **Подтверждение** для `missed` и SOS одной фразой «Да, подтверждаю» или кнопкой.
- `aria-live` для статуса голосового цикла.

## 7. Конфиденциальность

- Уведомление при первом включении: куда может уходить аудио (браузерный провайдер).
- Минимизация логов: не писать сырой текст в production-логи без явной настройки отладки.

## 8. Тестирование

- Юнит-тесты: `voice-intents.ts` (таблица фраз → intent).
- Ручные сценарии в Chrome (ru-RU): приём/пропуск, чек-ин, короткая фраза про давление.
- E2E опционально с заглушенным STT (инъекция текста в роутер).

## 10. Связанные решения

- Переключатель озвучки уже есть в UI и в БД (`voice_enabled`); голосовой **ввод** — новый функциональный слой, завязанный на тот же пользовательский «голосовой режим».
- После реализации обновить `docs/ai/CURRENT_STATE.md`, `domains/frontend-web.md`, при принятии архитектуры — запись в `DECISIONS.md`.

## 11. MCP и внешние источники (не входят в текущий этап)

- Отдельные **MCP-агенты** (интернет, файловая система устройства, др.) планируются **после** стабилизации голосового контура: сначала надёжный STT/TTS и безопасные локальные интенты, затем расширение через явно оговорённые инструменты с согласием пользователя и аудитом.
